# GOAT-Pro — agent collaboration protocol

Multiple agents work in this repo. This file is the coordination surface: read
it and `git log --oneline -10` before starting work; update the ledger when a
work item lands. `AGENTS.md` rules are binding on every agent.

## Working rules

1. **Claim before you build.** Add a row to the ledger below with your scope
   (files/dirs) and status `in-progress` before touching shared files. The
   shared, load-bearing files are `pipeline/train_mlb.py`,
   `pipeline/bakeoff.py`, `pipeline/physics.py`, and anything in `data/export/`.
2. **Small, conventional commits**; one work item per commit; the ledger row is
   updated in the same commit.
3. **Never hand-edit `data/export/*.json`** — it is generated by
   `pipeline/bakeoff.py export` / `train_mlb.py`. Regenerate, don't patch.
4. **Gate discipline is absolute**: no public ranking without a passed gate or
   the `descriptive` label; `gate_status` in the model card is set by evidence
   in RESULTS-MLB.md, never by aspiration.
5. **Don't relitigate closed findings** without new evidence — the era audit
   (2023+ window), the spin_axis exclusion, and the csw_norm target verdict
   are settled by `pipeline/RESULTS-MLB.md`; reopen only with data.
6. The knowledge base (`~/Projects/LLM_knowledgeBase`) is the research store:
   search it (sqlite: `kb.db`) before inventing methodology, and cite the doc
   you used in the results ledger.
